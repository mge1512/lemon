# Parsers in Go and Rust

This note is for people who write a grammar and want the parser in Go or in
Rust. It describes the two templates `tool/lempar.go` and `tool/lempar.rs`.

The grammar file is a Lemon grammar, as `lemon.html` describes it. The code
blocks and the actions are in the target language.

## Make a parser

    cc -O2 -o lemon tool/lemon.c
    ./lemon -Ttool/lempar.go query.y
    ./lemon -Ttool/lempar.rs query.y

The first command builds the generator. The second command writes
`query.go`, and the third command writes `query.rs`. The parser file is in
the directory of the grammar, or in the directory of the option `-d`. The
generator also writes the report `query.out`. There is no header file,
because the token numbers are constants in the parser file.

A grammar file with code is for one language. The rules can be the same for
all languages. The directory `test/recognizer/` shows one way. It has the
rules in one file and a short head for each language. The test script puts
the two parts together.

## The same as in C

- The parser takes one token for each call. The token number 0 is the end
  of the input.
- `%name` gives the first part of the function names. This note uses the
  default name `Parse`.
- The parser uses the same tables and takes the same steps as the C parser.
  The tests compare the trace messages of the three parsers.
- Precedence, `%fallback`, `%wildcard` and `%token_class` work as in C.
- `%stack_size` gives the largest number of entries on the parser stack.
  The default is 100. A parser that needs more calls the code of
  `%stack_overflow`.
- After a syntax error the parser calls the code of `%syntax_error` and
  drops the token. It reports the next error only after it has shifted three
  tokens. An error at the end of the input calls the code of
  `%parse_failure`. This is what `lempar.c` does for a grammar without the
  error symbol.
- A rule without action code gives its left side the value of the first
  symbol of its right side.

## Different from C

- The parser stack is a slice in Go and a `Vec` in Rust. It starts small
  and grows up to the limit of `%stack_size`. With `%stack_size 0` it has
  no limit. Keep a limit for input from a source that you do not control.
- The action code is copied without change, and each label of a rule is a
  local variable. In C the generator replaces each label with an expression.
- There is no header file and no `ParseFree`.

## Go

| Function | Purpose |
|---|---|
| `ParseAlloc() *yyParser` | Make a parser |
| `Parse(p *yyParser, major int, minor ParseTOKENTYPE, arg ParseARGTYPE)` | Give the parser one token |
| `ParseFinalize(p *yyParser)` | Empty the stack of the parser |
| `ParseInit(p *yyParser)` | Put a parser back into its first state |
| `ParseTrace(trace func(msg string))` | Turn the trace messages on, or off with `nil`. The setting is for all parsers of the package. |
| `ParseFallback(token int) int` | The fallback token of a token, or 0 |

Rules for the grammar:

- The code of `%include` starts with the package clause and the imports.
  The template has no imports of its own.
- `%token_type` and the types of `%type` are Go types. Without
  `%token_type` a token has the type `struct{}`.
- `%extra_argument` has a type only, for example `{*state}`. The code of the
  grammar reaches the value under the name `yyarg`. Without
  `%extra_argument` the type is `struct{}`, and the caller gives
  `struct{}{}`.
- Each label of a rule is a local variable in the action. The action gives
  the label of the left side its value.
- In the code of `%syntax_error`, `yymajor` is the number of the token and
  `TOKEN` is its value.
- The names that start with `yy` belong to the parser.
- A raw string in a code block must not end with a backslash. The reason
  is in `template-syntax.md`, under `literal-quotes`.

A part of `test/calc/calc-go.y`:

    %name Calc
    %token_prefix TK_
    %token_type {int}
    %default_type {int}
    %type exprlist {calcList}
    %extra_argument {*calcState}
    %include {
    package main

    type calcList struct{ n, sum int }
    type calcState struct{ result, count, nError, accepted int }
    }
    %syntax_error    { yyarg.nError++ }

    program ::= exprlist(L).               { yyarg.result = L.sum; yyarg.count = L.n }
    exprlist(A) ::= expr(B).               { A.n = 1; A.sum = B }
    expr(A) ::= expr(B) TIMES expr(C).     { A = B * C }
    expr(A) ::= NUMBER(B).                 { A = B }

A program that uses this parser:

    st := &calcState{}
    p := CalcAlloc()
    Calc(p, TK_NUMBER, 6, st)
    Calc(p, TK_TIMES, 0, st)
    Calc(p, TK_NUMBER, 7, st)
    Calc(p, 0, 0, st)
    CalcFinalize(p)
    // st.result is 42

The parser file has the line `// Code generated by lemon. DO NOT EDIT.`
before the package clause. It is not in the form that `gofmt` writes.

## Rust

| Function or field | Purpose |
|---|---|
| `ParseAlloc(arg: ParseARGTYPE) -> yyParser` | Make a parser. The parser owns the value of `%extra_argument`. |
| `Parse(p: &mut yyParser, major: i32, minor: ParseTOKENTYPE)` | Give the parser one token |
| `p.yyarg` | The value of `%extra_argument` |
| `ParseFinalize(p: &mut yyParser)` | Empty the stack of the parser |
| `ParseInit(p: &mut yyParser)` | Put a parser back into its first state. The value of `%extra_argument` stays. |
| `ParseTrace(p: &mut yyParser, trace: Option<fn(&str)>)` | Turn the trace messages of this parser on, or off with `None` |
| `ParseFallback(token: i32) -> i32` | The fallback token of a token, or 0 |

Rules for the grammar:

- The parser file is one module. A program uses it with a `mod` line. The
  file starts with `allow` attributes for the names and the unused parts of
  a generated parser. The code of `%include` comes after them.
- `%token_type` and the types of `%type` are Rust types. Without
  `%token_type` a token has the type `()`.
- The parser type has no lifetime parameter. For this reason the token
  type, the types of `%type` and the type of `%extra_argument` own their
  data.
- `%extra_argument` has a type only, for example `{State}`. In the code of
  the grammar, `yyarg` is a `&mut` reference to the value. Without
  `%extra_argument` the type is `()`, and the caller gives `()`.
- Each label of a rule is a local variable in the action. The variable owns
  the value: the parser moves it off the stack before the action. The
  action gives the label of the left side its value, and the compiler
  checks that it does so.
- In the code of `%syntax_error`, `yymajor` is the number of the token and
  `TOKEN` is a reference to its value.
- The names that start with `yy` belong to the parser.
- Write a brace or a double quote in a character literal as an escape:
  `'\x7b'`, `'\x7d'`, `'\x22'`. Do not put a double quote in a raw string.
  The reason is in `template-syntax.md`, under `literal-quotes`. Lifetimes
  and loop labels in a code block are possible.

The template has no `unsafe` code and uses only the standard library.

A part of `test/calc/calc-rs.y`:

    %name Calc
    %token_prefix TK_
    %token_type {i64}
    %default_type {i64}
    %type exprlist {CalcList}
    %extra_argument {CalcState}
    %include {
    pub struct CalcList { n: i64, sum: i64 }

    #[derive(Default)]
    pub struct CalcState { pub result: i64, pub count: i64, pub nError: i64, pub accepted: i64 }
    }
    %syntax_error    { yyarg.nError += 1; }

    program ::= exprlist(L).               { yyarg.result = L.sum; yyarg.count = L.n; }
    exprlist(A) ::= expr(B).               { A = CalcList { n: 1, sum: B }; }
    expr(A) ::= expr(B) TIMES expr(C).     { A = B * C; }
    expr(A) ::= NUMBER(B).                 { A = B; }

A program that uses this parser:

    #[path = "calc-rs.rs"]
    mod calc;
    use calc::*;

    fn main() {
        let mut p = CalcAlloc(CalcState::default());
        Calc(&mut p, TK_NUMBER, 6);
        Calc(&mut p, TK_TIMES, 0);
        Calc(&mut p, TK_NUMBER, 7);
        Calc(&mut p, 0, 0);
        CalcFinalize(&mut p);
        // p.yyarg.result is 42
    }

## What the templates do not have

The generator reports an error for these, and writes no parser file:

- Destructors: `%destructor`, `%token_destructor`, `%default_destructor`.
  In Go the garbage collector frees the values. In Rust the values are
  dropped when the parser pops them.
- `%realloc`, `%free` and `%stack_size_limit`
- The option `-m`

The generator writes a parser file for these, and the compiler of the
target language refuses the file with a message that names the feature:

- The error symbol in a rule
- `%extra_context`

The functions `ParseStackPeak` and `ParseCoverage` of the C template have no
translation.

## Errors when the parser runs

`Parse` panics for a token number that is not a terminal symbol of the
grammar. The C template has an `assert` for this case.

The left side of a rule gets its value in one of two ways:

1. The action gives the label of the left side a value.
2. The rule has no label for the left side. The value of the first symbol
   of the right side then stays and is the value of the left side.

The second way needs the same type for the two symbols. In Rust it also
needs a rule without a label for that first symbol, because a label moves
the value off the stack. If the types are not the same, or if the right side
is empty, the left side has no value of its type. A later action that reads
the value gets this:

- C: other data, read as the type of the symbol
- Go: the zero value of the type, or an old value of the same type
- Rust: a panic with a message that names the label

A grammar that gives each symbol a value before an action reads it does not
have this case.

## Tested with

The tests of this repository ran with gcc 13.3.0, Go 1.24.7 and rustc
1.97.0. The Rust parser of the calculator compiles without warnings for the
editions 2018, 2021 and 2024. Nobody has tested older compilers.
